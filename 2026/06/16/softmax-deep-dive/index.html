Softmax 的来历与 LLM 应用

2026年6月16日
#attention #deep-learning #llm #math #softmax

0. 先看结论

Softmax 做的事很直接：把一组分数变成概率分布。它的思想可追溯到统计物理里的 Boltzmann/Gibbs 分布，后来进入选择理论、统计学习和神经网络。到了 LLM 里，最常见的是两个位置：

  1. 输出层：把模型对所有 token 的打分 logits 变成“下一个 token 的概率”。
  2. 注意力层：把 query 和 key 的相似度分数变成“该看哪些上下文 token 的权重”。

在 MoE 模型里，softmax 还可能出现在 router 中，给不同 expert 分配路由权重。

几个容易混淆的点：

问题 答案
logit 越大是否概率一定越大？ 是。softmax 保序，最大 logit 对应最大概率。
logit 是不是百分比？ 不是。8.2 不代表 82%。
logit 可以是负数吗？ 可以。负数只表示相对分数低，不代表概率为负。
为什么不直接输出概率？ 任意概率分布不方便直接训练；模型先输出自由实数，再由 softmax 转成概率。
采样时一定要显式算 softmax 吗？ 不一定。greedy 只要找最大 logit；但随机采样、top-p 等通常需要概率或等价处理。

3. 历史由来：从物理到 LLM

Softmax 不是专门为神经网络凭空发明的。更贴近历史的说法是：归一化指数分布在多个学科里反复出现；“softmax”这个名字是在神经网络语境里流行起来的。

3.1 时间线

时间 关键事件 意义
1868 Boltzmann 分布 指数形式描述状态概率
1902 Gibbs 统计力学 partition function 等概念系统化
1959 Luce 选择公理 用相对偏好解释选择概率
1989 Bridle NIPS 论文 softmax 术语在神经网络语境中扩散
2001/2003 Bengio 神经概率语言模型 softmax 输出整个词表的下一个词概率
2005 hierarchical softmax 缓解大词表 full softmax 成本
2013 word2vec 负采样 用近似目标绕开大规模 softmax
2017 Transformer attention 中使用 scaled dot-product softmax
2017/2018 adaptive softmax / softmax bottleneck 系统讨论大词表效率与表达能力
2019/2020 nucleus sampling 基于 softmax 概率做动态截断采样
2022 FlashAttention 不改变结果，用 IO-aware 算法高效计算 attention softmax

4.3 神经网络线：Bridle 与 softmax 命名

在 1989 年 NIPS 论文中，John S. Bridle 将随机识别模型与神经网络训练联系起来，使用了归一化指数形式。随后 1990 年相关工作明确把神经网络分类输出解释为概率，使用 normalized exponential，也就是后来常说的 softmax。

从这以后，softmax 成为多分类神经网络的标准输出层之一。

8.1 扩展应用：MoE 路由里的 softmax

如果模型采用 Mixture-of-Experts（MoE）结构，softmax 还可能出现在 router 里。router 不选下一个 token，也不选上下文位置；它给当前 token 选择要经过哪些 expert。

位置 softmax 对象 输出含义
输出层 词表 token 下一个 token 的概率
注意力层 上下文位置 每个位置的信息权重
MoE router expert 列表 每个 expert 的路由权重

MoE 路由后面常接 top-k 选择，例如每个 token 只激活 1 个或 2 个 expert。这样可以让模型拥有更多参数，同时让每次推理只使用其中一小部分。普通 dense Transformer 没有这一层 router softmax。

9. 工程问题：为什么 softmax 不是“算一下”这么简单

9.1 数值稳定性

直接算 $e^{z_i}$ 可能溢出。例如 $e^{1000}$ 超出常规浮点范围。

稳定写法：

训练中一般不会显式先 softmax 再 log，而是用 fused 的 log_softmax + negative log likelihood 或 cross_entropy，减少溢出和精度损失。

这背后常用到 log-sum-exp 技巧：

它和“先减最大值再 softmax”是同一个稳定性思路：数学结果不变，但指数项不会过大。深度学习框架里的 log_softmax、cross_entropy 一般会在内部做类似处理。

9.4 softmax 饱和与梯度问题

如果某个 logit 远大于其他 logit，softmax 会非常接近 one-hot：

这会导致：

现象 影响
分布过尖 模型过度自信
梯度变小 学习信号变弱

Transformer 里的 $1/\sqrt{d_k}$ 缩放，就是为了缓解点积随维度增大而使 softmax 过尖的问题。

10. Softmax 与 LLM 解码参数

不少 LLM API 的生成参数，都是在 softmax 前后改概率分布。

参数/技术 发生位置 数学含义 效果
temperature softmax 前 $z_i \leftarrow z_i/T$ 控制随机性
top-k softmax 后或截断 logits 后 只保留最高 k 个候选 去掉低概率长尾
top-p / nucleus softmax 后 保留累计概率达到 p 的最小集合 动态候选集
repetition penalty softmax 前 降低已出现 token 的 logit 减少重复
logit bias softmax 前 手动提高/降低某些 token 的 logit 控制词汇偏好
greedy softmax 可省略 取最大 logit 确定性输出

10.1 top-k 和 top-p 的区别

示例：

token 概率 top-k=3 top-p=0.9
A 0.50 保留 保留
B 0.20 保留 保留
C 0.12 保留 保留
D 0.08 丢弃 保留
E 0.04 丢弃 丢弃
其他 0.06 丢弃 丢弃

top-p=0.9 会保留 A+B+C+D，因为累计概率 0.90。

这意味着 logits 会受到隐藏维度和输出矩阵秩的限制。Yang 等人在 “Breaking the Softmax Bottleneck” 中指出，许多基于 softmax 的语言模型存在表达能力瓶颈：自然语言的条件分布很复杂，而标准 softmax 输出结构可能限制模型能表示的分布族。

相关思路：

方向 代表思想 作用
Mixture of Softmaxes 多个 softmax 混合 用多个低秩分布组合出更高秩分布
更强 hidden state 增大模型深度/宽度 提高上下文表示能力
untied/tied embeddings 权衡 输入输出 embedding 是否共享 参数效率 vs 表达自由度
alternative output distributions sparsemax、entmax 等 让概率分布可稀疏或形状不同

现代 LLM 仍大量使用标准 softmax。softmax bottleneck 提供的是理解输出层限制的理论视角，不表示 softmax 已经被主流 LLM 淘汰。

12. 替代方案与变体

主流路线：

方法 用途 主要收益 主要代价
softmax 标准输出层/注意力 稳定、简单、生态成熟 大词表和长序列成本高
FlashAttention exact attention 实现 更快、更省显存 依赖内核和硬件实现
hierarchical softmax 大词表近似 降低 $O(V)$ 成本 树结构会影响效果
sampled softmax / NCE 训练近似 减少负类计算 有偏差/方差权衡

研究或特定场景：

方法 特点 适用场景
sparsemax 可产生 0 概率 希望分布稀疏
entmax softmax 与 sparsemax 折中 希望可控稀疏
adaptive softmax 高频词细算、低频词分簇 大词表语言模型
linear attention 不一定使用 softmax 追求低于 $L^2$ 的长上下文复杂度
Gumbel-Softmax 可微近似离散采样 训练含离散选择的模型

14. 常见误解

误解 更准确的说法
softmax 会“理解”概率 softmax 只做数值归一化，概率质量来自训练目标和数据
最大 logit 的 token 一定会被选中 采样时只是概率最大，不一定被抽中
temperature 是在 softmax 后调概率 通常是 softmax 前缩放 logits
attention softmax 输出的是词概率 attention softmax 输出的是上下文位置权重
mask 是 softmax 后把概率改成 0 常见实现是在 softmax 前把非法 logit 加上 $-\infty$
FlashAttention 是近似 attention FlashAttention 原始核心是 exact attention，只改变计算组织方式
softmax 概率就是模型“真实置信度” 神经网络概率可能未校准，不能直接等同真实可信度
训练时应该先手动 softmax 再算 cross entropy 多数框架的交叉熵损失应直接输入 raw logits
MoE router 的 softmax 是 token 概率 router softmax 输出的是 expert 权重，不是词表概率

15. 面向工程实践的检查清单

15.1 写 softmax 代码时

检查项 建议
是否减去 max 必须，避免 overflow
是否在训练中手写 softmax + log 尽量用框架的 fused cross entropy
mask 是否在 softmax 前加 推荐 pre-softmax mask
mask 值是否足够小 常用 -inf 或 dtype 可承受的极小值
fp16/bf16 下是否稳定 注意溢出、下溢和累加精度
损失函数是否期待 logits 先看框架文档，避免重复 softmax

15.2 调 LLM 生成时

想要的效果 可调参数
更确定、更保守 降低 temperature，降低 top-p
更有创意 提高 temperature，适度提高 top-p
减少胡言乱语 降低 temperature，限制 top-p/top-k
减少重复 使用 repetition penalty 或 presence/frequency penalty
禁止/鼓励特定词 使用 logit bias

16. 收束

Softmax 把“相对分数”变成“可训练、可采样、可解释的概率分布”。
它的历史大致经历了三次迁移：

在 LLM 中，softmax 同时参与两件事：决定下一个 token 的概率，以及决定上下文信息怎么流动。在 MoE 模型里，它还可能参与 expert 路由。公式本身不长，但围绕它会碰到大词表训练、长上下文注意力、采样策略、数值稳定、概率校准和表达能力瓶颈等问题。
